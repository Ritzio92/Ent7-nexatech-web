# Sesión 7 — Evidencia del MVP NexaTech

## 1. Problema y solución

Quiero mostrar un catálogo atractivo de tecnología y permitir a un usuario organizar una compra **ficticia** sin cuentas, servidores ni pagos. NexaTech resuelve este caso mediante una página web interactiva que permite explorar productos y calcular el subtotal en un carrito.

## 2. Prompt de desarrollo principal (marco R-C-O-I-R-F)

**Rol:** Actúa como desarrollador frontend senior con experiencia en diseño de interfaces para tiendas tecnológicas.

**Contexto:** Necesito una mini web publicable en GitHub y Vercel para una entrega académica del programa de IA aplicada. El público es un usuario peruano que navegará desde celular o escritorio.

**Objetivo:** Construye una tienda demo llamada NexaTech que permita descubrir tecnología y simular una selección de compra.

**Insumos:** Catálogo ficticio de 12 artículos tecnológicos con nombre, categoría, descripción, precio en soles e imagen ilustrativa. Categorías de laptops, audio, periféricos, monitores, accesorios y gaming.

**Restricciones:** Usa HTML, CSS y JavaScript sin framework ni backend; mantén el sitio estático y responsive. No implementes pagos, registro, compra real ni recopilación de datos personales. No utilices credenciales ni archivos secretos. Todos los precios y productos deben identificarse como demostración.

**Formato:** Entrega `index.html`, `styles.css`, `script.js`, recursos SVG, `README.md` e instrucciones de GitHub y Vercel. Incluye filtros, búsqueda, ordenación, favoritos, detalle, carrito con subtotal y botón de compra simulada.

## 3. Matriz del MVP

| Elemento | Definición |
|---|---|
| Objetivo | Explorar artículos tecnológicos y simular una compra |
| Usuario | Persona interesada en tecnología; uso móvil o escritorio |
| Funciones | Catálogo, búsqueda, filtros, carrito, subtotal y confirmación ficticia |
| Apariencia | Minimalismo tecnológico, azul oscuro, blanco y verde lima |
| Datos | 12 registros de catálogo ficticios, precios en soles, selección local |
| Restricciones | Sin backend, login, pagos, APIs ni datos personales |

## 4. Validación y mejora

**Prueba inicial prevista:** revisar buscador, categorías, agregar/quitar unidades y confirmar totales desde un celular y una computadora.

**Mejora implementada por diseño:** se añadió conservación local de carrito y favoritos, para que un refresco de página no haga perder la selección en el mismo navegador. **Esta mejora todavía debe validarse con un usuario real** para cumplir el requisito académico de iteración.
